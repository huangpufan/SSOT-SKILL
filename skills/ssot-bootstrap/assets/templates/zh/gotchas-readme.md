# 已知陷阱

     与失效由条目所有者持有。 -->

当改动触及一个已有反直觉陷阱的路径或操作时，使用本索引。先用触发条件匹配
任务，打开条目，在编辑或运行高风险步骤前遵循其中“不要这样做 / 改为这样做”
的一对动作。

例如，一个迁移助手看似可复用，但陷阱条目说明它会绕过正常写入所有者，此时
不要直接调用。打开条目，确认触发条件仍适用，采用它指出的安全路径，并运行
预防检查。

索引只负责路由。生命周期理由、事实与判断、证据是否仍有效、影响、原因、安全替代、
验证、所有者、预防以及解决或失效，都由陷阱条目拥有。

## 陷阱索引

| ID | 陷阱 | 记录状态 | 危险状态 | 触发提示 | 条目所有者 |
|---|---|---|---|---|---|
| GOT-NNNN | <陷阱> | current / archived / superseded | active / resolved | <路径、任务或操作> | [打开条目](./<topic>.md#got-nnnn) |

没有陷阱条目时，删掉示例行并显示下面这一行；出现真实条目后立即删掉本行：

空集合说明：原因=<具体理由>；负责人=[责任所有者](<可解析路径>)；复核条件=<可观察事件>。

每个真实条目必须且只能出现一行。编号与条目开头的 `id` 或固定格式的
`## GOT-NNNN` 标题相同；易读标题放在下一行的 H3 或粗体文字中，这样
`#got-nnnn` 锚点不会随标题变化。“条目所有者”链接必须能打开该文件或锚点；
两个状态都与条目一致。`record_status` 说明这份知识
是否仍是当前路由材料，`hazard_state` 说明陷阱是否仍存在。

这里的状态只是路由用短镜像。`active`（活跃）表示陷阱仍存在；`resolved`
（已解决）表示条目已解释
它为什么不再适用、什么变化使其失效。解释属于条目，不属于本索引。

兼容字段 `status` 可以继续存在，但必须镜像 `hazard_state`，不能拿它表示
`record_status`。

## 新增或更新陷阱

只有证据支持一个可重复、仓库特有的陷阱时，才创建条目。写明触发它的操作或
路径、可见失败、为什么直觉动作危险，以及更安全替代。条目存在后再加一行索引。
陷阱消失时，先更新条目，再在这里镜像 `resolved`。

仓库可以每条陷阱一份文件，也可以把相关陷阱放在同一主题文件中。聚合不改变
所有权：每条仍有固定 `## GOT-NNNN` 标题锚点，并在下一个 H2 前写明
**记录状态 / 危险状态**为 `current` / `active`，索引只链接该锚点一次。
旧“状态与触发”只能作为危险状态的兼容写法，不能补足记录状态。不要仅为迎合
索引表形状而拆分既有主题文件。

跨无关文件都适用的任务流程规则属于[开发](../../03-process/development/README.md)，
不属于本索引。有偿还计划的未完成改造属于[技术债](../tech-debt/README.md)。
已确认且尚未修复、已经修复或再次发生的缺陷属于[缺陷](../bugs/README.md)。

## 何时重新检查

触发路径、API、所有者、失败信号、替代方案或预防测试变化时复核条目。索引与
条目冲突时，以条目为所有者，修复索引镜像。
