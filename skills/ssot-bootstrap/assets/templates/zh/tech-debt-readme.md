当任务和一个已知妥协、临时表面或未完成重构重叠时，使用本索引。修改受影响
区域前先打开匹配条目，判断是现在修、现在推荐、显式延期，还是有证据地说明不在
本任务范围，再按条目的下一步和验证保护行动。

例如，API 改动触及一层登记为债务的兼容适配时，不要在读取关闭条件前再加一层
绕过。要么按指定检查移除适配，要么留下可见延期，保留所有者、原因、触发条件
和验证保护。

索引只按 ID、标题、短生命周期、优先级和条目链接路由。状态理由、事实与判断、
证据是否仍有效、影响、原因、取舍、偿还行动、验证、所有者、再次检查触发条件、
关闭和失效理由都由债务条目拥有。

## 债务索引

| ID | 债务 | 记录状态 | 偿还状态 | 优先级 | 条目所有者 |
|---|---|---|---|---|---|
| DEBT-NNNN | <债务> | current / archived / superseded | active / resolved / obsolete | `high`（高）/ `medium`（中）/ `low`（低） | [打开条目](./NNNN-<slug>.md) |

没有技术债条目时，删掉示例行并显示下面这一行；出现真实条目后立即删掉本行：

空集合说明：原因=<具体理由>；负责人=[责任所有者](<可解析路径>)；复核条件=<可观察事件>。

每个真实条目必须且只能出现一行。编号与条目开头的 `id` 相同；“条目所有者”
链接必须能打开该文件；两个状态都与条目开头一致。`record_status` 说明这份知识
是否仍是当前路由材料，`repayment_state` 说明债务仍待偿还、已经偿还，还是被
后续变化消除了需要。

`active`（活跃）表示债务仍影响决定，且有可证伪关闭路径；`resolved`（已解决）
表示已偿还并验证；`obsolete`（已失效）表示后续架构或决策移除了需要，条目会指出失效来源。理由属于条目，
本表只镜像状态词。

兼容字段 `status` 可以继续存在，但必须镜像 `repayment_state`，不能拿它表示
`record_status`。

## 怎样给重叠分类

- **现在修**：任务已经触及债务所有者，并能安全满足关闭条件。
- **现在推荐**：债务会实质改变本次设计或风险，但偿还需要新权限或范围。
- **显式延期**：本任务无需加深债务也能继续；在条目或关联工作项保留原因、所有者、
  下一步、触发条件和验证保护。
- **不在范围**：只有证据表明任务不重叠债务路径、所有者、失败方式或验收边界
  时才成立。

## 创建或更新条目

只有真实妥协或未完成改造有影响且有具体偿还路线时才创建条目，不能把模糊愿望
写成债务。条目存在后再添加索引行。状态变化时，先更新条目的证据、关闭或失效，
再在这里镜像生命周期。

## 边界，以及何时重新检查

有根因修复生命周期的可观察缺陷属于[缺陷](../bugs/README.md)；没有计划偿还的
陷阱属于[陷阱记录](../gotchas/README.md)；难逆方向属于
[决策](../decisions/README.md)。触发路径、所有者、临时表面、架构决策、
关闭条件或验证保护变化时复核债务。
