## 第一天阅读顺序

1. **定位** — 读本页的一句话定位和目录地图，先判断问题属于哪类 owner。
2. **理解产品** — 读 [01-product/README.md](./01-product/README.md)，了解产品为谁
   服务、今天实际可用什么，以及什么结果算成功。
3. **理解架构响应** — 读 [02-architecture/README.md](./02-architecture/README.md)，
   沿当前请求到结果的故事找到相关运行时 owner。
4. **进入任务 owner** — 按任务进入架构 view/domain、流程 owner 或长期记录；只读
   当前任务需要的分支。
5. **检查水位** — 动手前读 [STATUS.md](./STATUS.md)，确认协议/覆盖水位、开放裁决
   与可见缺口。

## 问题到 owner 的地图

| 读者问题 | 第一个 owner | 证据方向 |
|---|---|---|
| 产品承诺什么、限制什么、怎样验收？ | [产品](./01-product/README.md) | 当前产品界面、验收证据与用户源资料 |
| 当前系统怎样兑现产品承诺？ | [架构](./02-architecture/README.md) | 运行轨迹、代码、schema、配置与测试 |
| 应按什么流程开发或验证？ | [流程](./03-process/README.md) | 命令、CI、测试策略、benchmark 与发布/部署规范 |
| 哪个历史决策、BUG、债或陷阱会影响本次工作？ | [记录](./04-records/README.md) | 条目生命周期及证据/关闭 owner |
| 仓库专有词是什么意思？ | [术语表](./glossary/README.md) | 统一定义与唯一 owner 指针 |

产品解释用户意图，架构解释技术响应；流程文件告诉贡献者怎样工作，记录文件保存
长期例外或决策为何存在。不要在两个区域同时维护同一条事实。
