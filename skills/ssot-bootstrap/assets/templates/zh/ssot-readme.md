<一句话仓库定位>

SSOT 是“单一事实源”：每条长期事实只在一个位置解释和维护。这个位置叫事实
所有者（owner），它通常是一个文件或小节，不一定是某个人。默认读者是实施
委托者：你可以不读代码，但仍应看懂要让 Agent 交付什么、结果在哪里可见、什么
证据能验收，以及何时停止或升级处理。

“追踪基线”说明文档目前追踪到哪个提交、会话和协议版本；“登记表（register）”
只记录状态与指针，不承担解释正文；“何时复核”说明哪些变化要求重新检查；
“当前、目标与缺口状态”说明一项事实已经落地、仍是方向，还是缺少答案。协议把
入口、动作与结果称为产品表面（product surface）：产品表面是人能看到、调用或
收到的内容；运行时所有者（runtime owner）是实际处理
请求或持有状态的系统部分。Q01-Q21 是二十一类质量、风险与治理路由编号，不是
评分；它们把问题分别指向产品、架构、流程/证据和缺口所有者。

## 目录地图

```text
SSOT/
├── 01-product/          用户需要、当前界面、旅程与产品验收
├── 02-architecture/     系统响应、运行时所有者、流程、状态与信任边界
├── 03-process/          开发、测试、基准、部署、发布，以及适用时的运维和安全合规流程
├── 04-records/          决策、缺陷、技术债、陷阱与研究记录
├── glossary/            仓库专有名词
├── STATUS.md            追踪基线、区域状态、开放裁决与可见缺口登记表
├── HISTORY.md           只追加的批次写入日志：哪个技能在何时写了哪些文件
└── README.md            本阅读入口
```

目录地图只回答“从哪里开始”，不替代答案本身。进入子目录后，由该目录 README
解释边界，并继续指向长期事实的唯一所有者。

## 第一天阅读顺序

1. **定位** — 读本页的一句话定位和目录地图，先判断问题属于哪类所有者。
2. **理解产品** — 读 [01-product/README.md](./01-product/README.md)，了解产品为谁
   服务、今天实际可用什么，以及什么结果算成功。
3. **理解架构响应** — 读 [02-architecture/README.md](./02-architecture/README.md)，
   沿当前请求到结果的故事找到相关运行时所有者。
4. **进入任务所有者** — 按任务进入架构视图/领域、流程所有者或长期记录；只读
   当前任务需要的分支。
5. **检查追踪基线与裁决边界** — 动手前读 [STATUS.md](./STATUS.md) 确认追踪到的提交、
   会话、协议、开放裁决与可见缺口，并核对下方 [裁决边界](#裁决边界) 表：表内规则
   由人类决策建立，改动这些规则本身须交人裁决，不能由 Agent 自行改写。

如果要把实现交给代理，走完路线后至少写清：产品结果、当前架构所有者、有界
流程、可见验收，以及任何 Q01-Q21 风险或缺口所有者。这才是最小可用的改动
委托；只给一个组件名不够。

## 问题到所有者的地图

| 读者问题 | 第一个所有者 | 证据方向 |
|---|---|---|
| 产品承诺什么、限制什么、怎样验收？ | [产品](./01-product/README.md) | 当前产品界面、验收证据与用户源资料 |
| 当前系统怎样兑现产品承诺？ | [架构](./02-architecture/README.md) | 运行轨迹、代码、数据结构、配置与测试 |
| 应按什么流程开发或验证？ | [流程](./03-process/README.md) | 命令、CI、测试策略、基准测试与发布/部署规范 |
| 哪个历史决策、缺陷、债或陷阱会影响本次工作？ | [记录](./04-records/README.md) | 条目生命周期及证据/关闭所有者 |
| 仓库专有词是什么意思？ | [术语表](./glossary/README.md) | 统一定义与唯一所有者指针 |
| 哪项质量、风险或治理条件会改变任务？ | [STATUS Q 登记表](./STATUS.md#质量风险与治理) | Q01-Q21 的唯一产品、架构、流程/证据与缺口所有者 |
| 哪些规则不能由 Agent 自行修改？ | [裁决边界](#裁决边界) | 每条规则的 owner 正文与建立依据 |
| 交给实现代理什么，最后怎样验收？ | 产品 → 架构 → [流程](./03-process/README.md) | 当前承诺与边界、具体所有者/路径、可见成功/失败/恢复，以及合适证据 |

产品解释用户意图，架构解释技术响应；流程文件告诉贡献者怎样工作，记录文件保存
长期例外或决策为何存在。不要在两个区域同时维护同一条事实。
