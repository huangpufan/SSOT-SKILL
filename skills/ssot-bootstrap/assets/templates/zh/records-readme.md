把本目录看成仓库的案件柜。它既保存已经结束的历史，也保存仍开放但已有名字的
工作。来这里时先带一个具体问题——“这个故障以前出现过吗？”、“为什么选择这个
方向？”或“哪些已知工作不能继续恶化？”——再打开唯一条目所有者，按其中的当前
状态、证据和跟进动作处理。

例如，修改存储代码时出现熟悉故障，可以先按症状或触发条件扫缺陷和陷阱
索引。打开匹配条目，检查证据是否仍新鲜，运行它指定的预防检查；真正修改运行时
行为前，再回到当前架构所有者。

本目录不重新定义当前产品承诺或架构。[产品](../01-product/README.md)拥有用户
今天可以依赖什么，[架构](../02-architecture/README.md)拥有系统今天怎样运行。
记录可以解释历史、理由或开放风险并链接这些所有者，但不能覆盖它们。

## 选择记录类型

- [决策](./decisions/README.md)解释难逆选择、备选方案和实现状态。
- [研究](./research/README.md)保存有边界的证据包，直到长期所有者吸收其中
  可复用结论。
- [陷阱](./gotchas/README.md)提醒可重复陷阱，并把“不要这样做”和更安全替代
  配成一对。
- [缺陷](./bugs/README.md)保存值得长期保留的失败方式知识，包括尚未修复、已经
  修复，以及修好后再次发生的问题。
- [技术债](./tech-debt/README.md)追踪已知妥协或未完成改造，并给具体偿还和关闭
  路径。

按下一位读者要做的决定分类，不按源文件所在目录分类。一个事件可以链接多条
记录，但每项事实、状态理由和关闭条件只能有一个条目所有者。

## 索引与条目所有权

每个子 README 都只是索引。它显示稳定 ID、记录本身的生命周期状态、该记录类型
描述的另一条现实状态轴，以及指向条目所有者的 Markdown 链接。决策另看实现状态，
研究另看结论采纳状态，缺陷另看失败状态，陷阱另看危险状态，技术债另看偿还
状态。两条轴分开后，就不会把“文档仍是当前知识”误解成“工作已经完成”。
触发条件与时间、生命周期理由、事实与判断、证据与失效条件、
影响、原因或理由、备选、行动、验证、跟进、关闭/失效、R15 受影响范围边界与
R16 安全/隐私/合规/客户暴露义务都由条目文件拥有。适用 Q14-Q21 的当前事实
仍由产品、架构或流程所有者持有；记录只保存相关决定、事故、证据、缺口和复核
触发器，不重新定义当前隐私、安全、人工监督、公平、生命周期、输出或商业事实。
条目事实变化时，不能只改索引。

## 创建或更新记录

只有出现真实决策、调查、陷阱、已确认且尚未修复/已修复/再次发生的故障或债务时才创建条目。先写读者要做
的决定和下一步，用合适证据核实事实，指出什么会使记录失效，再添加一行指针大小
的索引。没有合适类型时，先暴露所有者缺口，不要把叙述藏进索引单元格。

## 何时重新检查，以及冲突时怎么办

触发路径、所有者、关联实现、证据来源、决策或关闭信号变化时，复核记录。
记录和当前所有者冲突时，保留历史、诚实更新生命周期，并把读者路由到当前
所有者；不要悄悄把历史改写成今天的结论。
